# Duplicate Hunter — الدليل العربي

**Duplicate Hunter** أداة سطر أوامر محلية مكتوبة بلغة Python لاكتشاف الملفات **المتطابقة بايتًا ببايت**. تؤكد الأداة التطابق الكامل باستخدام SHA-256، وتحسب المساحة التي تمثلها النسخ الزائدة، ويمكنها إنشاء تقرير JSON أو نقل النسخ الزائدة إلى مجلد عزل بعد معاينة صريحة.

> الأداة لا تحذف الملفات المكتشفة تلقائيًا، ووضع العزل يكون معاينة فقط ما لم يُستخدم الخيار `--apply`.

## المتطلبات

- Python 3.10 أو أحدث.
- صلاحية قراءة الملفات والمجلدات المطلوب فحصها.
- لا تحتاج إلى حساب أو خدمة سحابية أو API Key أو قاعدة بيانات.

## كيف يكتشف الملفات المتطابقة؟

يعتمد المشروع على ثلاث مراحل مترابطة حتى لا يقرأ كل ملف كاملًا دون حاجة:

1. **الحجم الدقيق:** الملفات ذات الأحجام المختلفة لا يمكن أن تكون متطابقة بايتًا ببايت.
2. **بصمة أولية:** الملفات المتساوية في الحجم تُجمع بحسب SHA-256 لأول 64 KiB.
3. **SHA-256 كامل:** الملفات المرشحة فقط تُقرأ بالكامل، ولا تُعلن مجموعة مكررة إلا بعد تطابق البصمة الكاملة.

البصمة الأولية وسيلة لتقليل العمل فقط وليست حكمًا نهائيًا على التطابق.

أثناء الفحص تتجاهل الأداة الروابط الرمزية، وتتجاهل الملفات والمجلدات المخفية افتراضيًا، وتتجاوز الملفات التي لا يمكن قراءتها. كما تستخدم هوية الملف في نظام الملفات لمنع احتساب الرابط الصلب نفسه كنسخة مادية إضافية أثناء الفحص.

## فهم النتيجة

لكل مجموعة ملفات متطابقة تعرض الأداة:

- عدد الملفات المتطابقة.
- حجم كل ملف.
- المساحة القابلة للاستعادة من النسخ الزائدة.
- بصمة SHA-256 الكاملة.
- ملفًا واحدًا بعلامة `KEEP`، والنسخ الإضافية بعلامة `DUP`.

يتم ترتيب المجموعات بحيث تظهر المجموعات ذات المساحة القابلة للاستعادة الأكبر أولًا.

## تقارير JSON

يمكن حفظ نتيجة الفحص في تقرير مناسب للأرشفة أو الأتمتة:

</div>

```bash
duplicate-hunter ~/Pictures --json duplicate-report.json
```

<div dir="rtl">

يتضمن التقرير وقت الإنشاء بصيغة UTC، والمجموعات، والمسارات، والبصمات، والأحجام، والمساحة المهدرة في كل مجموعة، والإجمالي القابل للاستعادة.

## العزل بدل الحذف

المعاينة هي الوضع الافتراضي:

</div>

```bash
duplicate-hunter ~/Pictures --quarantine ~/DuplicateQuarantine
```

<div dir="rtl">

هذا الأمر يعرض خطة النقل فقط ولا ينقل الملفات.

بعد مراجعة الخطة يمكن التنفيذ صراحةً:

</div>

```bash
duplicate-hunter ~/Pictures --quarantine ~/DuplicateQuarantine --apply
```

<div dir="rtl">

عند التنفيذ:

- تحتفظ الأداة بنسخة واحدة من كل مجموعة.
- تنقل النسخ الإضافية إلى مجلد العزل.
- تتعامل مع تعارض أسماء الملفات بإضافة رقم إلى الاسم.
- تنشئ ملف `duplicate-hunter-manifest.json` يحتوي على مسار المصدر والوجهة وبصمة SHA-256 لكل ملف تم نقله.

لا توجد حاليًا وظيفة استعادة تلقائية. يمكن الاستفادة من ملف الـ manifest لإعادة الملفات يدويًا عند الحاجة.

## خيارات سطر الأوامر

| الخيار | الوظيفة |
|---|---|
| `paths` | ملف أو أكثر أو مجلد أو أكثر للفحص |
| `--no-recursive` | عدم الدخول إلى المجلدات الفرعية |
| `--include-hidden` | تضمين الملفات والمجلدات المخفية |
| `--min-size BYTES` | تجاهل الملفات الأصغر من الحجم المحدد |
| `--json FILE` | إنشاء تقرير JSON |
| `--quarantine DIR` | إعداد خطة عزل للنسخ الزائدة |
| `--apply` | تنفيذ عمليات النقل المخطط لها |

القيم السالبة في `--min-size` تُرفض.

## الخصوصية والأمان

المشروع لا يحتوي على عميل شبكة أو Telemetry. عملية القراءة والحساب تتم محليًا. لكن تقرير JSON قد يحتوي على مسارات ملفات وبصمات؛ لذلك يجب اعتباره ملفًا قد يتضمن معلومات حساسة عند مشاركته.

قد تتغير الملفات بواسطة برنامج آخر بين لحظة الفحص ولحظة النقل، لذلك لا يمكن اعتبار المعاينة ضمانًا ضد جميع حالات التزامن. بالنسبة للبيانات المهمة، احتفظ بنسخة احتياطية وراجع الخطة قبل استخدام `--apply`.

راجع [SECURITY.md](SECURITY.md) لحدود الأمان و[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) لشرح البنية الداخلية.

## حدود النسخة الحالية

المشروع حاليًا لا يقوم بـ:

- مقارنة الصور بصريًا للعثور على الصور المتشابهة.
- فحص الملفات داخل الأرشيفات.
- اعتبار الاسم أو التاريخ دليلًا على التطابق.
- الاستعادة التلقائية من مجلد العزل.
- حذف النسخ تلقائيًا.
- توفير واجهة رسومية.

هذه حدود فعلية للنسخة الحالية وليست ميزات ضمنية.
